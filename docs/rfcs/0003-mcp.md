# RFC 0003: Local MCP server for tandem agent control

- **Status:** proposed for the maintainer; implemented in the same change for review
- **Requested in:** [discussion #21](https://github.com/crisprintsstuff/OxyBrush/discussions/21)
- **Changes:** AGENTS.md hard rule "No telemetry. No network calls"

## Problem

Sculptors using an AI coding agent want that agent to work in the same
scene they are working in: look at the model, make a stroke, remesh, and
hand the tool back. OxyBrush's rule is that the program makes no network
calls except the opt-in updater ([RFC 0002](0002-updates.md)). A useful
agent integration has to fit that rule. A cloud API, a telemetry channel,
or a socket open on the LAN would not.

## Decision

An **opt-in, local-only** [Model Context Protocol](https://modelcontextprotocol.io)
server. A fresh install never listens and never speaks MCP. Automated runs
(`--screenshot`) force it off, the same way they force the updater off.

Settings > **Local AI agent** turns it on. The choice is remembered. The
session token is not: every launch mints a new one, and Disconnect mints
another, so a token copied into a chat log stops working when the session
ends.

### Where it listens

| Mode | Transport | Who it talks to |
|---|---|---|
| Desktop app, opt-in | HTTP on `127.0.0.1:<ephemeral port>/mcp` only | A client that presents this session's bearer token |
| `oxybrush-cli mcp [file]` | stdio, Content-Length framing (no socket) | The process that spawned it |
| `oxybrush-cli mcp --attach 127.0.0.1:PORT --token …` | stdio in, loopback HTTP out | The already-running app |

The desktop listener binds `127.0.0.1` and drops any accepted peer that is
not loopback. It does not bind `0.0.0.0`, a LAN address, or IPv6. Every
request needs `Authorization: Bearer <token>` (32 bytes of OS entropy,
hex-encoded). If an `Origin` header is present it must be
`http://127.0.0.1` or `http://localhost` for this port; anything else is
rejected, which stops a web page from driving the server through DNS
rebinding. The `Host` header must be loopback too. There is no outbound
connection: the server never dials, and tool arguments that look like URLs
are refused. `--attach` refuses any address that is not `127.0.0.1` or
`localhost`.

### Tandem control

The user keeps sculpting. Agent requests are applied on the UI thread
through the same editor paths as the menus (history, jobs, atomic saves).
While the user is mid-stroke, mid-gizmo or mid-selection, a mutating tool
waits; read-only tools (`scene_info`, piece info, `screenshot`) still run.
Orbiting and panning are not interrupted.

Long work (remesh, decimate, subdivide) uses the existing background job
(`Editor::start_job`). The window stays responsive; the tool call returns
when the job finishes. The headless CLI has no UI thread, so the same tools
run synchronously in that process.

Every agent edit is an ordinary undo step whose label starts with
`Agent: `, so it shows in the history and undoes like a stroke the user
made. Opening another project does not discard unsaved work unless the
agent passes `discard: true`. Saves and exports are atomic. Export refuses
to overwrite the open project or a file that was opened or imported in this
session.

### On screen

While an authenticated request has arrived in the last 45 seconds, the
status bar shows **Agent connected — Disconnect**. One click drops the
indicator and rotates the token; the opt-in stays on, and the new token is
in Settings. Unchecking the setting stops the listener.

`screenshot` returns a PNG of the 3D viewport (not the panels) as an MCP
image, in the same pixel space as screen-space stroke points. The CLI has
no viewport and returns an error for that tool. Screen points in the CLI
are an 800×600 virtual view of the file.

### What is not sent

Nothing leaves the machine. No account, no usage data, no crash data, no
upload of the screenshot or the mesh. A client the user configured may of
course be a local front-end for a cloud model; that program's own network
traffic is outside OxyBrush. OxyBrush does not add a way to reach it.

### Dependencies

Pure Rust, same licenses as the rest of the workspace (MIT / Apache-2.0).
JSON is `serde_json`, already in the tree. The session token uses
`getrandom` (already pulled in by the updater) for OS entropy. No `unsafe`,
no C toolchain, no TLS. The protocol crate `oxy-mcp` does not depend on
wgpu, winit or egui.

## Tools

`scene_info`, `list_pieces`, `piece_info`, `select_piece`, `open`, `save`,
`import`, `export`, `add_primitive` (sphere, cube, plane), `select_brush`,
`set_brush` (size and strength), `set_symmetry`, `stroke` (world or screen
points), `mask` (clear, fill, invert, blur, sharpen, grow, shrink, cavities,
peaks), `remesh`, `decimate`, `subdivide`, `undo`, `redo`, `set_camera`,
`screenshot`.

Setup for common clients is in [docs/mcp.md](../mcp.md).

## Alternatives considered

- **Cloud relay or account-backed agent:** rejected. It breaks the privacy
  rule and is not needed for tandem sculpting.
- **On by default:** rejected, same reason as the updater.
- **Listen on all interfaces with a token:** a token can leak into a shell
  history or a screenshot; binding loopback removes that whole class of
  mistake.
- **stdio only, no listener in the app:** cannot attach to a document the
  user already has open. The listener is what makes tandem mode possible;
  `--attach` covers clients that can only launch a process.
- **A new undo stack for the agent:** the user could not undo an agent
  stroke with Ctrl+Z, and the two stacks would fight. One history, labeled,
  is the invariant the app already has.

## Follow-ups

- More tools as the matching editor features settle (transform gizmo,
  alphas, subdivision levels, vertex color).
- Server-sent events for clients that cannot POST to a Streamable HTTP
  endpoint. `--attach` covers those clients today.
- A file-root sandbox tighter than "the user account the app is running
  as", if tandem use shows that agents wander into unrelated paths.
